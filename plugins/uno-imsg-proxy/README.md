# uno-imsg-proxy

Uno's iMessage style: how Uno comes across in Messages. It fills gaps in the
stock iMessage plugin (reactions, typing, bubbles, link previews) and keeps
error text out of chats. The guardrails live in
[uno-guard](../uno-guard/README.md), whose hooks run first. The owner's Uno
may change this plugin itself (uno-admin skill): a test per change, the
owner's OK, then install and restart.

Install: `openclaw plugins install ./plugins/uno-imsg-proxy --force --accept-capabilities`,
then restart. Code: `index.js` (the hooks), `rules.js` (pure rules,
unit-tested in `test/uno-imsg-proxy*.test.js`). It never throws into a turn.

Settings (`plugins.entries.uno-imsg-proxy.config`; who the admin is and the
owner's name come from uno-guard's settings):

| Key | Default | What |
|---|---|---|
| `imsgPath` | `/opt/homebrew/bin/imsg` | imsg for tapbacks, custom emoji, rich links and bubbles |
| `ackEmoji` | 👀 | Got-it reaction for a browser task or a slow turn |

## What it does

| Guard | Why it exists | Delete it when… |
|---|---|---|
| **No pre-pass.** Replies and reactions are the model's; nothing runs before it except typing in one-on-ones. A quick pass (a small decision model) used to pick tapbacks, decide whether a group message was for Uno, and send an early 👀, all from the last five messages; it misread banter and missed messages meant for Uno (Sept 30). The 👀 got-it comes with the turn's first browser call | The quick pass's reactions and gating were wrong too often | Never |
| **Group chats: Uno decides.** The family group has `requireMention: false`, and `agents.defaults.silentReply.group` is `allow`, so every message reaches the model, which answers, reacts, or stays silent; a message that names Uno always gets an answer (OpenClaw's rule). No typing shows until a bubble goes out, since the model may stay quiet | A quick pass deciding relevance from five messages kept Uno quiet when a family member asked it something and when the owner said "Uno" (Sept 30) | OpenClaw's ambient room events support iMessage |
| **Own-message redirect.** A react aimed at one of Uno's own messages is blocked with the id of the sender's latest message | imsg labels a thread reply's target with the chat's handle even when Uno sent it, so the model reacted to itself | imsg reports the right sender for Uno's messages |
| **Reaction and reply targets.** A react or threaded reply must name a specific message the current sender sent, in the chat the turn came from (a group session's own group; a one-on-one chat never reaches into a group); never Uno's own. If the model leaves the ID out, uno-imsg-proxy answers with the exact ID of the sender's latest message so the model retries correctly | The model often omitted the ID, and the stock plugin then fell back to the chat's latest message, usually Uno's own reply (Uno hearted itself on day one). The plugin is general-purpose and doesn't check whose message it is | OpenClaw refuses id-less reacts and supports a "sender only" rule |
| **Custom emoji reactions.** 🎉 🔥 💯 👀 🙏 ✅ and other emoji go out through `imsg tapback --emoji`, confirmed in the Messages database; the classic six stay on OpenClaw's path. A failure asks the model for a few words instead, as the persona says. Needs the patched imsg (`patches/`, install guide "Custom emoji reactions"); with stock imsg the model is told to use one of the classic six | The stock plugin maps only the six classic tapbacks and rejects anything else | The stock plugin sends custom emoji |
| **Error scrub.** Error payloads, or OpenClaw's exact error formats ("⚠️ …", "Something went wrong while processing your request", "use /new…", Codex harness failures), are replaced with a plain line worded for who's talking, and logged at ERROR so Healthchecks counts them. Normal answers that happen to say "please try again" pass | The stock pipeline delivers raw error text to the chat | OpenClaw lets you hide error text per channel |
| **Typing and the got-it reaction.** OpenClaw's typing is off (`agents.defaults.typingMode: "never"`); the plugin shows typing while the model works (refreshed every 5 s, stopped at Uno's first message or reaction, or after 3 minutes) and for 0.6–1.5 s before each bubble. The first browser call of a turn stops the typing and reacts 👀; 15 s of work with nothing sent also reacts 👀; a react call stops it at once. Web search doesn't count. Per-message state is in claim files in the OS temp folder, because plugin copies share no memory | OpenClaw showed typing for the whole turn, 47 s on a browser task, with nothing else to say the message had landed. Its ack reaction doesn't cover iMessage | OpenClaw can stop typing per tool and react on iMessage |
| **Link previews.** A message, or a paragraph bubble, that is only a URL goes out with `imsg send-rich --url` (a message's plain copy is cancelled) | OpenClaw's sends carry no preview data (checked in the Messages database) | The stock plugin sends rich links |
| **No opening name in groups.** In a group chat, a reply that opens with a household first name and a comma or colon (the owner, `uno-family-memory` names, website owners) loses it (`dropOpeningName`) | Replies are threaded to the message they answer, and the model kept opening with a name, once the wrong one, even when told not to (Sept 30) | The model reliably stops on its own |
| **No restart notice.** OpenClaw's "I'm continuing your interrupted request now (the gateway has just restarted)…" is cancelled at the send (`isRestartNotice`) | A restart mid-turn posted it in the family group (Sept 30); it has no setting, and typing and the got-it reaction already say Uno is on it | OpenClaw makes the notice optional |
| **Approval prompts untouched.** A message with "approval required" and an `/approve …` line skips every rewrite here (bubbles, names, em dashes) (`isApprovalPrompt`) | OpenClaw links a 👍 to the approval by the exact text it sent; split into bubbles, the 👍 did nothing (Sept 30) | Never |
| **Bubbles, all on the thread.** A reply with paragraphs goes out as one iMessage per paragraph (up to 6; code blocks stay whole): OpenClaw sends the first, threaded on the message it answers; each of the rest follows on that same thread through `imsg send-rich --reply-to`, after a typing pause. The thread is OpenClaw's reply target when it's a message guid, else the one the first bubble landed on in the Messages database; a reply that opens with a link threads on the message being answered. A threaded send that fails goes out unthreaded | OpenClaw's `chunkMode: newline` packs paragraphs into one message under the 4,000-character limit, and block streaming doesn't split replies on the Codex harness (checked Sept 28). The extra bubbles went out through `imsg send`, which can't thread, so only the first was on the thread (Oct 1) | OpenClaw splits paragraphs into separate threaded messages on the Codex harness |
| **No em dashes.** Outbound "—" becomes ", " or ". " | Persona style rule, enforced in code | Never; it's cheap |
| **One-emoji replies.** A reply that's a single emoji goes out as a tapback on their latest message instead of a big emoji bubble (`tapbackFor`); if the tapback fails, the text goes | Uno answered "Thanks" with a big 👍 and then a 👍 tapback (Sept 30) | Never |
| **Reactions are react calls.** AGENTS.md tells Uno to react with `message` → `react` and an emoji (no messageId: OpenClaw falls back to the message being answered, and this plugin points an id-less react at the sender's latest message). A reply that opens with a lone emoji also goes out as a tapback on their unanswered latest message, with the rest as text (`leadingReaction`). In test sessions (`agent:<id>:test:…`) a react is logged as `test react <emoji>` and reported done, for the evals (`npm run eval`) | Uno wrote reaction emoji into its text and never called react (Sept 30: no react calls in real or test turns; AGENTS.md asked for a messageId the model never sees) | OpenClaw's `reactionLevel` guidance covers iMessage |
| **AGENTS.md for sandboxed agents.** A `before_prompt_build` hook adds the agent's own workspace `AGENTS.md` to the system prompt (`appendSystemContext`) for every sandboxed agent (`sandboxedSession`). On the Codex harness OpenClaw leaves `AGENTS.md` to Codex's project-doc discovery, which searches the working folder; for a sandboxed agent that's the container path, so nothing was found and the prompt report said `native_unverified` | Sept 30: the family group's agent answered NONE for facts that exist only in `AGENTS.md` and never followed its reaction rules; after the hook, the family, second-person and website agents all quoted it | OpenClaw injects or snapshots `AGENTS.md` for sandboxed Codex agents |
| **Reply shape next to each message.** A `before_prompt_build` hook adds the agent's workspace `REPLY.md`, when there is one, next to each chat message (`appendContext`; one-on-one, group and test sessions, not scheduled jobs or helpers; `chatTurn`), and `CALL.md` instead on a FaceTime call (`callTurn`: `agent:<id>:facetime:…` and call evals), marked as a setup note so it isn't answered as their words (REPLY.md stays unmarked: marked, it lost its hold on research replies) | Sept 30: the same instructions in `SOUL.md` or `AGENTS.md` (six wordings, real turns) left a researched comparison at 5 to 7 texts plus 3 or 4 links; next to the message it came back as one text and one link, with the same research and the full breakdown when asked | The model follows reply-shape rules from the persona files after a long research run |

## Known limits

- **The hook is synchronous.** A custom emoji send holds the gateway for the
  send plus up to 4 s of confirmation (usually about 0.1 s).
